# API and data

The OpenAPI specs are the source of truth for behaviour, and the SQL migrations
are the source of truth for shape. Neither is generated from the other.

| Page | Read it when |
| --- | --- |
| [API standards](../API_CONTRACTS.md) | You are adding or changing an endpoint and need the house rules. |
| [Curl examples](../API_EXAMPLES.md) | You want a runnable request for every operation. Generated — do not edit. |
| [Contracts](../CONTRACTS.md) | You need the payload contracts that cross service boundaries on Redis Streams. |
| [API versioning](../API_VERSIONING.md) | You are about to change something already shipped under `/api/v1`, which is frozen. |
| [Schema audit](../API_SCHEMA_AUDIT.md) | You want optional and nullable reported separately across the aggregate spec. Generated. |

## Spec first, always

Behaviour absent from `services/<name>/openapi.yaml` does not exist. Edit the
spec, then run `make contracts SVC=<name>`; the generated `gen/` directory is
committed and CI fails when it drifts.

The gateway builds a fail-closed route registry from every service spec at boot.
An unknown permission refuses boot and an unknown route returns 404, so a new
endpoint is unreachable until its spec says who may call it.
